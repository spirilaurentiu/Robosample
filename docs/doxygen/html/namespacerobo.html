Apply the deterministic BAT-scaling map by factor s and return both the scaled positions and the log-Jacobian the map actually realized.

Parameters
[in]modelImmutable model (topology and z-matrix).
[in]atomPosInInput Cartesian positions; not mutated.
[in]sScale factor applied to the scaled BAT coordinates.
[in]anchorRPer-body bond-length anchor mu_r, keyed by the scaled body's placed (zI) atom index; a missing key defaults to 0.
[in]anchorThetaPer-body bond-angle anchor mu_theta, same keying.
[out]outNScaledCount of DOFs the map actually displaced (may be below countScaledDofsStatic in degenerate geometry).
[out]outLnJacThe Cartesian log-Jacobian (J(x')-J(x0)) + outNScaled*ln(s), consistent with outNScaled.
Returns
A scaled copy of the positions; atomPosIn is unchanged.
Postcondition
outLnJac is the log-Jacobian of the geometry actually produced, so it matches the map (INV-7); outNScaled is the count used to form it.
Warning
The paired map is an exact involution (M_{1/s,mu} o M_{s,mu} == identity) ONLY when both legs share the SAME anchor mu. A caller SHALL pass the SAME frozen anchorR / anchorTheta to both partners of a swap pair in one round (INV-7); see BatAnchorStats.
Note
outLnJac depends on mu because the produced geometry x' = f(x0, s, mu) does; only the map's local determinant s^N is anchor-independent.
Limitation: a scaled body whose parent is itself Ground-adjacent has no zK reference atom, so its angle DOF is silently skipped (omitted from both outNScaled and outLnJac, kept self-consistent). Production configurations SHOULD avoid stacking a scaled joint directly on a root-adjacent body. See the module findings.

Time derivative columns dH_FM/dt (in F) of the velocity Jacobian.

Parameters
[in]jtJoint type.
[in]X_FMThis body's cross-mobilizer transform.
[in]V_FMCross-mobilizer spatial velocity in F (V_FM[0] = w_FM, V_FM[1] = v_FM).
[out]HdotRate columns written to Hdot[0..dof-1].
Postcondition
Identically zero for the seven joints whose H_FM is constant in F; the engine calls this only for BendStretch, SphericalCoords, and FreeLine, whose M axes rotate. These feed the mobilizer-bias (Coriolis) acceleration.
Note
The HDot / Coriolis path has historically hidden silent energy-pumping bugs, so the BendStretch, SphericalCoords, and FreeLine cases are pinned by three independent oracles (OQ-2 closed): the external Simbody differential TestRoboticsOracle.{BendStretch,SphericalCoords,FreeLine} compares the HDot-dependent udot / A_GB at 1e-8; JointJacobianDot.HDotMatchesDerivativeOfHFM checks HDot_FM == d/dt jointH_FM by finite difference; and Integrator.UnderValidatedJointsConserveEnergy / BendStretchIsolatedConservesEnergy are the energy-conservation oracle.

void robo::advanceQuatExp ( const Real *  q0,
const Vec3 &  wF,

Real *  q1 
)

Advance a unit quaternion by an exponential-map step under a constant angular velocity.

Parameters
[in]q0Initial unit quaternion (4 components).
[in]wFAngular velocity expressed in the PARENT frame F, consistent with the engine's qdot = 1/2 (0,wF) (x) q left-multiply map.
[in]hTime step.
[out]q1Advanced quaternion (4 components).
Postcondition
q1 is unit by construction (the exponential map composes two unit quaternions), so the overflow-to-zero failure of a linear q += h*qdot drift cannot occur (INV-9).
Reversible: negating wF maps q1 back to q0, which HMC reversibility relies on. As h -> 0 it reduces to the linear drift q0 + h*qdot0.

Compute the Route-B normal-mode analysis at the configuration currently held in state and return its softest non-rigid mode.

Parameters
[in]modelImmutable model (topology, masses, joint layout).
[in,out]stateState whose coordinates define the analysis point; perturbed during finite differencing and restored to the input configuration before return.
[in]hFinite-difference step along each generalized-speed direction (radians for torsions).
[in]zeroTolEigenvalues with |omega^2| <= zeroTol are treated as rigid/external/noise modes and skipped when selecting the soft mode (about 6 near-zero per Free-rooted molecule; 0 for an all-Rigid-rooted torsional world).
Returns
A RouteBNMA with ascending eigval, the u-space modes, the chosen softMode, and the unit-norm uScaleFactors direction.
Precondition
OpenMM is initialized (post Context::initialize), model is a built internal-coordinate world (not Cartesian), and state holds the energy-minimized configuration q0.
Postcondition
state is left realized at the input q0; the analysis has no other observable effect on program state (it does not set the sampler's scale factors, draw momenta, or run acceptance). For nu == 0 the result is empty.
Note
Cost is 2*nu OpenMM force evaluations plus nu sqrt(M^-1) sweeps.
See also
RobotEngine::multiplyBySqrtMInv, VelocityDistortion

auto robo::quaternionDotFromAngVel ( Real  qw,

Parent-frame quaternion kinematic map \( \dot q = N(q)\,\omega_{FM} \).

Parameters
[in]qwScalar component of q (the orientation R_FM of the body frame M in its parent F, as built by Rotation::fromQuaternion).
[in]qxVector component of q, x.
[in]qyVector component of q, y.
[in]qzVector component of q, z.
[in]wGeneralized angular velocity w_FM, expressed in the parent frame F.
Returns
qdot as a Vec4, the left Hamilton product \( \tfrac12 (0,\omega)\otimes q \).
Warning
The w argument SHALL be expressed in the parent frame F to match the standard R_FM convention of Rotation::fromQuaternion. Feeding a body-frame angular velocity (the right-product map) advances the orientation with a wrong-handed velocity and pumps kinetic energy (INV-9).
Note
Single source of truth: Quat::angVelToQdot and Rotation::convertAngVelToQuaternionDot both delegate here, so the two quaternion-derivative paths cannot diverge.
