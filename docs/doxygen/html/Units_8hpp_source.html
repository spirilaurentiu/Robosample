3// units_md.hpp -- boundary unit safety for robosample, built on the
4// nholthaus compile-time units library (third_party/units/units.h, MIT).
5//
6// POLICY: typed quantities live ONLY at I/O boundaries (prmtop parsing, the
7// OpenMM transfer, DCD writing, timestep configuration) where unit-system
8// mistakes actually happen -- Angstrom vs nm, kcal vs kJ. The dynamics core
9// stays raw `double` in the consistent MD system (nm, dalton, ps, kJ/mol);
10// there is nothing to mix up once past the boundary, so paying for dimensional
11// analysis inside the ABA recursion would be cost with no benefit. nholthaus
12// unit_t is zero runtime overhead, but the ergonomic + compile-time cost is
13// only worth it at the edges. The conversions below are the exact spots that
14// have bitten us (e.g. the DCD nm->Angstrom x10).
15//
16// Add the submodule and point the include path at it:
17// git submodule add https://github.com/nholthaus/units third_party/units
18// target_include_directories(robosample PRIVATE third_party/units/include)
19// ============================================================================
